# 决策：中文排版与语言自动检测（2026-09-12）

已实施

## 问题

项目最初面向英文小说设计，中文书稿存在以下问题：
- 中文文件名经 slugify 后被全部过滤，输出退化为 `book.html`
- `count_words` 按空白分词，中文无空格导致统计严重失真（11264 字的书只算出 463 词）
- `lang` 硬编码默认 `en`，中文书需要手动写 front-matter
- 首字下沉（`::first-letter`）对汉字比例失调
- 书籍感模式下章节标题用 italic，中文斜体可读性差
- 强调（`em`）用斜体，中文没有斜体传统
- 段首缩进 `1.6em` 不符合中文出版两字符规范
- 书末和目录统一写"词"，中文应为"字"

## 决策

- **slug 保留中文**：`SLUG_RE` 增加 `\u4e00-\u9fff` 区间，中文文件名直接用作输出名
- **字数统计双语**：中文字符直接计数，剩余非中文部分按空白分词，两者相加
- **语言自动检测**：正文中文字符占比 >15% 判定为 `zh`，front-matter 显式指定优先
- **`[lang="zh"]` 专属 CSS**：
  - 禁用首字下沉（汉字方块字下沉后字形比例失调）
  - 章节标题取消 italic，改正常加粗
  - 段首缩进从 `1.6em` 改为 `2em`
  - blockquote 取消 italic
  - `em` 改用 `text-emphasis: filled dot` 着重点
  - `line-break: strict` 避免标点出现在行首
  - 默认行距微调至 1.9
- **字体栈增强**：serif 新增 SimSun、Source Han Serif SC
- **模板文案自适应**：`book.lang == 'zh'` 时显示"字"，否则"词"

## 替代方案

- **用 pypinyin 把中文 slug 转拼音**：否决。中文文件名在 Windows/macOS/Linux 均合法，转拼音反而丢失可读性且增加依赖
- **引入 jieba 做中文分词后统计词数**：否决。中文出版惯例说"字数"不说"词数"，按字符计数更符合读者预期，且零依赖
- **全局统一用"字"替代"词"**：否决。英文书说"词"更准确，应按语言分别显示
- **中文也保留首字下沉但调整大小**：否决。汉字是等宽方块，首字下沉后与正文行高对齐困难，且中文出版无此传统
- **用 `font-style: italic` 模拟中文斜体**：否决。浏览器对中文的 faux italic 是倾斜变换，字形变形严重，可读性差

## 影响

- 中文书稿无需任何 front-matter 即可正确编译，输出文件名、字数、语言、排版全部自动适配
- 英文书稿行为完全不变（回归测试 42/42 通过）
- 产物体积增加约 1.5 KB（中文 CSS 规则），可接受
- 后续新增语言支持只需加 `[lang="xx"]` 规则和检测阈值，架构可扩展
