# 决策：用 GitHub Pages 自动发布最新书稿（2026-09-12）

已实施。

## 问题

- `dist/*.html` 编译出来后，上线依赖人工操作。
- 目标是 `content/*.md` 的改动推到 `main` 后自动上线，本地零手动步骤。
- 仓库原为私有，Pages 在私有仓库上不可用。

## 决策

- 仓库转公开，用 GitHub Pages + GitHub Actions 发布。
- 发布源取 CI 重编译的结果，配三道闸门：产物与源码同步、零外部依赖、全产物回归。
- 站点入口固定 `index.html`，线上只保留一份产物。
- 「发布哪一本」以 `content/*.md` 的提交时间为判据，不看产物。

## 替代方案

- **保住私有仓库 + 另建公开产物仓库**：需要跨仓库 PAT，链路多一跳，换来的只是源码不公开。
- **升级 GitHub Pro 在私有仓库开 Pages**：站点仍然公开，付费买不到站点私密性。
- **按 `dist/*.html` 的 mtime 挑最新**：`actions/checkout` 把所有文件的 mtime 统一写成检出时刻，CI 里必然挑错。
- **按 `dist/*.html` 的提交时间挑最新**：产物是渲染结果，任何一次重建都会改写它，其提交时间恒等于「最后一次重建」且彼此相同，判据每次退化到平局。
- **把挑选逻辑内联在 workflow 的 bash 里**：本地跑不了，唯一的验证机会全押在 CI 上。

## 影响

- 源码与书稿正文对所有人可见，站点对任何拿到链接的人公开。
- `dist/` 与 `content/` 必须继续入库：产物是模板唯一备份源，也是 CI 同步闸门的比对基准。
- `verify.py` 必须能逐产物运行并返回非零退出码，否则 CI 假绿。
- 支持多书并存需要改按 slug 分路径发布，并补目录页。
