# 决策：翻页方式从「拖拽跟手 + 惯性」改为「纯点击」（2026-09-10）

已实施。

## 问题

第一版实现了完整的拖拽翻页：手指横拖时页面实时跟随，松手按位移 + 速度判定翻页或回弹。

实际用下来手感不好。具体表现：

- 位移跟手稳定，但松手后的吸附动画在 CSS 多列 + 重排下不够顺，视觉上有"顿一下"
- 需要处理一堆边界：轴向锁定、首帧速度噪声、边缘阻尼、甩动阈值、连点合并
- 修复"只跟手第一帧"的 bug 时发现，问题出在一个与拖拽无关的点击守卫上（`if (!tapCandidate) return;` 吃掉了后续 touchmove），说明这套逻辑的耦合面已经超出可控范围

## 决策

**移除全部拖拽手势，只保留点击翻页。**

- 左 30% / 右 30% 点击翻页，中间 40% 开合工具栏
- 补三个点击模式专有的细节：90ms 连点合并窗口、首末页回弹 + 文字提示、翻页方向光影 `#pagehint`
- 过渡曲线改为 `.38s cubic-bezier(.22,1,.36,1)`：起步略快、末段缓收

## 替代方案

- **保留拖拽但改用 `scrollLeft` 驱动**：否决。正是为了绕开 Chrome 55+ 的多列 `overflow` 渲染 bug 才用的 `translate3d`，退回 `scrollLeft` 等于把已知坑重新踩一遍。
- **保留拖拽但去掉惯性，只做跟手 + 回弹**：否决。去掉惯性后，长短拖动的手感差异反而更明显（拖很远却回弹），比纯点击更不可预期，且仍要维护整套手势状态机。
- **用第三方翻页库（如 `turn.js`、`page-flip`）**：否决。与「产物零外部依赖」的全局规则直接冲突，且这类库面向纸质书翻页拟物动画，与本项目的"极简阅读"定位不符。
- **点击 + 键盘，但保留轻扫（swipe）作为快捷方式**：否决。轻扫必须依赖速度阈值判定，而阈值在真机上的手感差异极大，等于把拖拽的判定复杂度留下了一半、收益只多一个手势。

## 影响

- 删除约 110 行手势代码（`Flipper` 模块整体移除），新增约 50 行 `Pager`
- 交互路径从「连续手势」变为「离散点击」，与"翻一页"这个动作本身的语义更一致，可预期性提升
- `tests/verify.py` 的用例从「惯性判定 4 场景」改为「点击分区 / 横滑不误触 / 连点合并」，验证成本下降
- 阅读场景下长按选词不再与翻页手势冲突
