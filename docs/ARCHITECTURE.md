# md-to-single-html-ebook 架构说明

## 核心目标

Markdown 进，自包含单文件 HTML 出。

- 输入：用 `##` 分章的 Markdown 书稿
- 输出：单个 `.html`，样式、脚本、正文全部内联
- 读者：手机浏览器，离线可用
- 反目标：不做构建工具、不引框架、不产生运行时依赖

## 不可破坏的约束

| 约束 | 原因 |
|---|---|
| 产物零外部引用 | 离线、邮件、U 盘分发的前提 |
| 产物字节可复现 | 同一份源码在任意平台重建必须逐字节相同，否则每次重建都是整篇假 diff |
| `column-width` 用绝对长度 | 百分比对它是非法值，浏览器静默丢弃声明 → 退回单列、正文溢出屏外 |
| 多列容器宽高同时固定 | 「宽高完美限制」才形成一列一页 |
| `overflow: hidden` 只放 `#stage` | Chrome 55+ 对 overflow 非 visible 的多列容器有渲染 bug，第 3 栏之后整片不显示 |
| JSON 注入不走 autoescape | 引号会被转成 `&#34;`，`JSON.parse` 直接失败 |
| 产物以 LF + UTF-8 写出 | 写文本会用平台默认换行，Windows 产 CRLF，破坏可复现性 |
| 正文区点击只翻页 | 一旦给点击加第二语义（开菜单），阅读时就会误触；工具栏只能由小圆点开关 |
| 沉浸与全屏成对翻转 | 沉浸 = 收起工具栏 + 进全屏，展开 = 显示工具栏 + 退全屏。只翻一半就会停在「没有全屏、也没有工具栏」的空档 |
| 发布产物与源码同步 | 产物是模板的唯一备份源，而线上发布的是 CI 重编译的结果。两者一旦漂移，线上看到的东西就不再能从仓库 `dist/` 复现 |

## 数据流

`content/*.md` → `generator.py` → `dist/*.html`

1. 解析 front matter 与 `##` 章节
2. markdown-it-py 渲染正文 HTML
3. 读入模板三份文件：CSS / JS 原样内联，HTML 走 Jinja 渲染
4. 正文用 `Markup()` 注入，给 JS 的数据 `json.dumps` 后把 `< > &` 转成 `\uXXXX`
5. 以 LF + UTF-8 写字节

## 发布链路

`content/*.md` → push `main` → GitHub Actions → 编译 → 三道闸门 → 取最新产物 → GitHub Pages

- 站点：<https://zlzayn.github.io/md-to-single-html-ebook/>
- workflow：`.github/workflows/publish.yml`
- 触发范围：改动落在 `content/`、`templates/`、`generator.py`、`pick_artifact.py`、`verify.py`、`pyproject.toml`、`uv.lock` 或 workflow 自身。
- 只改文档不触发发布。
- 兜底入口：`workflow_dispatch`，可用 `artifact` 输入手动指定产物。

### 「最新产物」的判定

判据是**书稿源 `content/*.md` 的提交时间**，不是产物自己的。

- 产物是渲染结果，任何一次重建都会改写 `dist/*.html`。
- 产物的提交时间因此恒等于「最后一次重建」，且同一次重建会让所有产物时间相同。
- 按产物时间选，每次都会退化到平局，与「哪一本最近在动」无关。
- 只有书稿源的提交时间能反映维护者实际在写哪一本。

优先级（实现见 `pick_artifact.py`）：

1. **显式指定** —— `--requested <文件名>`，对应 `workflow_dispatch` 的 `artifact` 输入。
2. **对应 `content/*.md` 的提交时间最大者**。
3. **平局按产物文件名升序**，保证结果确定。

- 时间取自 `git log -1 --format=%ct -- <path>`，需要 `fetch-depth: 0`（浅克隆拿不到完整历史）。
- 不用 mtime：`actions/checkout` 把所有文件的 mtime 统一写成检出时刻，按 mtime 取必然挑错。
- 产物到源文件的映射复用 `generator.slugify`，同一套命名规则不在两处各写一份。
- 判定过程把候选表与选定依据打进日志，线上选错时可回溯。

### 站点入口固定为 `index.html`

- `逆流.html` 直接发布时 URL 会被编码成 `%E9%80%86%E6%B5%81.html`。
- 发布前统一重命名为 `index.html`，站点入口恒为根路径。
- 入口因此天然指向最近改动的那一本，正好实现「只发最新一个」。

### 三道闸门

| 闸门 | 判据 | 挡住什么 |
|---|---|---|
| 产物与源码同步 | 重编译后 `git diff --exit-code -- dist/` 为空 | 产物与源码漂移，破坏「产物是模板唯一备份源」 |
| 零外部依赖 | `grep -oE '(src\|href)="https?://[^"]*"' dist/*.html` 无命中 | 外链样式 / 脚本 / 字体混进产物，破坏离线能力 |
| 全产物回归 | 对 `dist/*.html` **逐个**跑 `verify.py` | 阅读器行为回归 |

闸门只圈 `dist/`，本地因 uv 镜像配置改写 `uv.lock` 之类的噪声不会误触。

### 发布源是 CI 重编译的结果

- 流水线不在云端提交任何东西。
- `dist/` 始终由维护者本地重跑 `generator.py` 后提交。
- 云端重编译只用于验证与发布，这依赖「产物字节可复现」这条约束。

### 站点公开性不可配置

- 已发布站点对任何拿到链接的人公开。
- 仓库可见性与站点可见性互相独立。
- Free / Pro / Team 都只能在站点公开的前提下发布。
- 站点级访问控制只有 Enterprise Cloud 组织的 Pages access control 提供。
- 书稿里不得出现密钥或内部信息。

## 设计决策

### 进度用字符偏移而非页码

页码随字号、行距、屏宽变化，字符偏移不随。

- 保存时换算成全书归一化偏移（0~1）
- 恢复时按偏移反查所在页
- 实现上维护「文本节点 → 全书起始偏移」索引表，支持双向换算与二分查找

### 分页用 CSS 多列 + `translate3d`

epub.js、起点阅读页等成熟方案的共同做法。

- 真实列宽由 JS 实测后注入 `--col-w`，CSS 侧只接受绝对值
- padding 放在 `#stage` 而非 `#book`，让列宽等于内容宽
- 翻页写 `transform: translate3d()`，不用 `scrollLeft`：绕开多列容器的 overflow 渲染 bug，同时启用 GPU 合成

### 章节跳转的定位修正

章节标题偏移常落在上一页尾部（标题前有留白），直接反推会错位到上一章。

- 用标题元素的实际视觉列号校验并修正页码
- 短暂锁定目标章节，读者翻离后自动解除

### 点击分区只分左右，不设中间态

- 命中面就是整块 `#viewport`，按中轴线分左右半屏，不做独立热区元素
- 左侧 50% 上一页、右侧 50% 下一页，中线上归右侧
- 无中间态：中部点击不会弹出底部工具栏，工具栏只由右上角小圆点与 `Esc` 控制
- 滚动模式下左右分区不翻页，交给纵向滚动

### 章节滑块已移除

- 滑块与目录、页码三者职责重叠，拖动精度也差
- 章节跳转只保留目录抽屉一条路径

### 安全注入

- Jinja2 `autoescape=True`，正文 HTML 用 `Markup` 包装
- 给 JS 的数据先 `json.dumps`，再把 `< > &` 转成 `\uXXXX`，杜绝 `</script>` 逃逸
- JSON 注入必须绕过 autoescape，否则引号变 `&#34;`

### 性能

- 全书一次性渲染，不做虚拟化
- 翻页只写 `transform`，过渡交给 CSS，主线程不参与逐帧计算

## 交互模型

### 常驻控件

整个界面平时只有一个极淡的小圆点。

- 静默态不透明度 18%，不干扰阅读
- 展开态圆点变为胶囊，提示可收起
- 首次进入短暂显现（1.6 s），之后保持静默

### 沉浸态与全屏是同一个状态

小圆点切换的两个方向都是复合动作，不存在只改一半的中间态。

| 状态 | 下方工具栏 | 浏览器全屏 |
|---|---|---|
| 沉浸 | 收起 | 进全屏 |
| 展开 | 显示 | 退全屏 |

三条配套规则：

- **首次手势补全**：浏览器要求全屏由用户手势触发，默认的沉浸态无法在加载时进全屏，因此首次真实交互（非小圆点）时补一次，避免「默认沉浸却始终不全屏」。
- **系统层面退出全屏要跟着走**：按 `Esc` 或用手势退出全屏时，自动把工具栏展开并唤醒圆点，不让界面停在无控件状态。
- **`Esc` 收起工具栏即回沉浸**：走同一条切换路径，全屏一并跟上。

- 全屏 API 不可用时（如 iOS Safari）静默降级，只保留工具栏的收放

### 抽屉排版

两个抽屉共用一套栅格，保证纵向对齐可校验。

| 抽屉 | 栅格 |
|---|---|
| 目录 | 序号列定宽右对齐（tabular-nums）+ 标题列左对齐；长标题换行后悬挂对齐在标题列 |
| 设置 | 标签列定宽 + 控件列自适应；7 组行共用同一对左右边界 |

- 当前章用底色 + 左侧 2px 强调条标记
- 设置组之间用 1px 分隔线，最后一组不加线

### 翻页反馈

- 翻页瞬间从对应方向扫过一道极淡渐变光影（`#pagehint`），提供方向反馈
- 首 / 末页不静默无响应，给一次 14px 回弹 + 文字提示

## 防错清单

| 症状 | 机制 | 处置 |
|---|---|---|
| `ImportError: cannot import name 'Markup' from 'jinja2'` | Jinja2 3.1 把 `Markup` 移到 markupsafe | 改 `from markupsafe import Markup` |
| 浏览器 `JSON.parse` 抛错，引号变 `&#34;` | `payload_json` 走了 Jinja autoescape | 用 `Markup()` 包裹并手写 `< > &` → `\uXXXX` |
| 分页只出 1 页，正文溢出屏外 | `column-width: 100%` 是非法值被丢弃 | 改绝对长度，由 JS 实测注入 `--col-w` |
| 目录跳章后高亮差一章 | 标题偏移落在上一页尾部，`pageAtOffset` 返回前一章页码 | 用标题实际视觉列号校正 + `_pinnedChapter` 短暂锁定 |
| 拖拽翻页只跟手第一帧 | `touchmove` 的 `if (!tapCandidate) return;` 吃掉后续移动事件 | 守卫与拖拽逻辑解耦；拖拽方案已整体移除，现为纯点击 |
| 每次翻页圆点闪一下 | 翻页与 `touchstart` 都调 `UI.awaken()` | `awaken()` 只保留在首次进入与展开工具栏时调用 |
| Windows 下重建产物体积变大、整篇 diff | `write_text` 走平台默认换行，LF 翻成 CRLF | 写 bytes，先归一 `\r\n` → `\n` |
| 同字节产物在不同机器上页数不同 | Chromium 版本与系统字体度量差异 | 断言避免写死总页数，只断言相对变化 |
| 按 Esc 退出全屏后停在无工具栏的空档 | 全屏被系统层面改动，工具栏状态没跟上 | 监听 `fullscreenchange`，全屏丢失且工具栏收起时自动展开并唤醒圆点 |
| 默认沉浸态始终不进全屏 | 浏览器禁止无手势的全屏请求 | 首次真实交互时补一次，且跳过小圆点自身（否则会进全屏又立刻退） |
| 模板被误删后无法恢复 | 模板只存在于工作区，产物是唯一副本 | 产物自包含 ⇒ CSS / JS 可逐字反推，HTML 骨架可据 `generator.py` 的注入变量还原；见下节 |
| 发布流水线挑错产物 | ① `actions/checkout` 把所有文件的 mtime 统一写成检出时刻，「取 mtime 最大」失效；② 产物是渲染结果，一次重建会同时改写全部产物，其提交时间恒等于「最后一次重建」且彼此相同 —— 拿它当判据，每次都退化成按文件名排序 | 判据改用**书稿源** `content/*.md` 的提交时间（`git log -1 --format=%ct`）并设 `fetch-depth: 0`；实现见 `pick_artifact.py` |
| `verify.py` 全绿，CI 却放行了失败 | 脚本原本只打印统计，从未设置退出码，恒返回 0 | 末尾补 `sys.exit(1 if FAIL else 0)` |
| 排序靠后的产物从未被验证 | `verify.py` 写死 `_TARGETS[0]`，只测字典序第一个 | 支持命令行指定目标；CI 用 `for f in dist/*.html` 逐个覆盖 |
| 私有仓库里找不到 Pages 开关 | 个人 Free 账号的 Pages 只支持公开仓库（分支保护接口返回 403 付费墙即同一限制） | 仓库转公开，或升级 Pro（站点仍公开） |
| 断言只对某一本书成立 | `verify.py` 写死「目录 10 行」、跳章抽样 `[0, 3, 6, 9]`，隐含「书稿有 10 章」 | 书稿相关的量（章数、页数、词数）一律从 `#bookdata` 的结构化字段读取，或写成相对关系；模板层的规格常量（按钮数、分组数）具名提到文件顶部 |

## 契约

- `dist/*.html` 不出现任何 `http(s)://` 的 `src` / `href`
- 模板三份 `.j2` 编译期内联；只有 `reader.html.j2` 走 Jinja 渲染逻辑，改 CSS / JS 不需要懂 Jinja
- 写产物一律写 bytes 并归一 LF
- 任何改动后重跑 `verify.py`，产物必须零外部引用
- `verify.py` 有失败项必须返回非零退出码
- 断言不得写死与书稿相关的量：章数、页数、词数一律从产物自身读取或写成相对关系，否则断言只对某一本书成立
- 发布前必须通过三道闸门：产物与源码同步、零外部依赖、全产物回归
- 站点入口恒为 `index.html`，线上只保留一份产物

## 模板可恢复性

产物把模板逐字内联，因此模板是**可反推的**，这是本项目的一条隐含保障。

- `reader.css.j2` = 产物 `<style>` 与 `</style>` 之间的内容
- `reader.js.j2` = 产物最后一个 `<script>` 与 `</script>` 之间的内容
- `reader.html.j2` = 产物去掉上述两块后的骨架，把渲染结果替换回 `generator.py` 注入的变量

判定还原是否精确的方法：用还原出的模板重建，与既有产物逐字节比对。相同即还原无损。
